## 1. Context of the Organization (Clause 4.1)

- [ ] Identify internal factors (small team size, high mobility, personal devices).
- [ ] Identify external factors (data privacy laws like DPDP Act, cyber threats, market competition).

## 2. Interested Parties & Requirements (Clause 4.2)
- [ ] List all external parties (Buyers, Sellers, Regulators, Cloud Vendors, Banks).
- [ ] List internal parties (Broker/Owner, Field Agents, Admin Staff).
- [ ] Map legal/regulatory requirements (DPDP Act, RERA compliance, Tax laws).

---

## 3. ISMS Scope Definition (Clause 4.3)
- [ ] Define physical boundaries (Main office address, remote/field work environments).
- [ ] Define logical boundaries (Google Workspace / M365 tenant, CRM, Cloud Storage).
- [ ] Define information boundaries (Client KYC, Financial Ledgers, Agreements).
- [ ] Document explicit exclusions (e.g., third-party bank payment processing systems).

---

## 4. Asset Inventory & Data Flow Mapping
- [ ] List all hardware assets (Laptops, Mobile devices, Routers).
- [ ] List all software/SaaS assets (Email, CRM, WhatsApp Business, Cloud Drives).
- [ ] Map data lifecycle: Collection -> Storage -> Transmission -> Retention -> Destruction.

---

## 5. Initial Risk Scenario Identification (Clause 6.1 Baseline)
- [ ] Unencrypted KYC data stored on personal phones (Shadow IT / BYOD).
- [ ] Lack of central offboarding procedure when field agents leave.
- [ ] Absence of automated data deletion policies for past candidate or client records.
- [ ] Single point of failure (Owner holding all admin credentials without emergency backup).
